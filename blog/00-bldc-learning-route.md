# 00 BLDC 完整学习路线：从真实电机现象到固件、无感与 FOC

一台 BLDC 即使已经观察到相电流，也可能不转、反转，或者一加负载就失速。电流只有在正确的转子位置和换相顺序下才会持续产生正转矩；电磁转矩还必须大于负载转矩与摩擦转矩，机械速度才能建立。

调试这三类问题时，要沿能量和信息链逐层定位：直流母线是否经三相桥形成目标相电流，三相 `e·i` 之和是否为正电磁功率，电磁转矩是否足以克服负载，Hall 反馈是否把下一次换相放在正确扇区。

把这些现象放到同一条因果链中，故障位置就能缩小到功率级、电机参数、位置反馈或控制器。关键是保留每一层的输入、输出和状态量，不要只看最终转速。

配套仓库：[https://github.com/Old-Ding/BLDC](https://github.com/Old-Ding/BLDC)

## BLDC 的能量与信息闭环

BLDC 系统可以沿同一条能量与信息链理解：

```text
直流母线
  -> 三相逆变器
  -> 三相电流
  -> 反电动势与电磁转矩
  -> 机械转速和位置
  -> Hall / 反电动势 / 编码器反馈
  -> 换相、电流和速度控制
  -> 三相逆变器
```

沿这条链排查故障时，一次只改变一层，并继续观察上一层的输入与输出。这样才能区分“门极命令正确但电流路径错误”“电流存在但转矩方向错误”和“电磁转矩正确但负载过大”等不同根因。

## 工具为什么要分工

| 工具 | 负责什么 | 证据边界 |
|---|---|---|
| PLECS / Simulink | 开关功率级、电机电磁量、机械负载和完整闭环 | 主图来自真实模型求解，不由信号示意图替代 |
| MATLAB | 参数计算、控制器设计、批量扫参和 PLECS CSV 后处理 | MATLAB 图必须说明数据来源和模型层级 |
| C | 换相、Hall、测速、PI、保护和状态机 | C 源码需要编译和测试后才能声称可执行 |
| Python / PowerShell | 调用工具、编排场景、导出数据和报告 | 自动化只负责运行与留证，不重复实现技术判断 |

验证任一控制结论时，可以沿下面的证据链向前回查：

```text
模型或源码
  -> 命名场景
  -> CSV / trace
  -> PLECS Scope 主图
  -> MATLAB 对比或扫参
  -> 指标与 PASS/FAIL 报告
  -> 教学正文
```

只看正文中的结论还不够。模型或源码说明系统实际执行了什么，CSV 和 Scope 波形给出原始响应，MATLAB 图用于比较场景，指标报告负责判断结果是否满足预先定义的条件。

## 阶段 A：功率级与电机物理基础

| 篇章 | 核心问题 | 读完后应能解释 |
|---:|---|---|
| 01 | 相电流怎样形成转矩，负载过大为何失速 | `电流 -> 转矩 -> 净转矩 -> 速度` |
| 02 | 三值相命令怎样变成六路门极信号 | 上桥、下桥、悬空和直通的电流路径 |
| 03 | 机械角度、电角度和极对数怎样关联 | 机械转一圈为什么可能经历多个电周期 |
| 04 | 梯形反电动势怎样参与转矩形成 | `ea*ia + eb*ib + ec*ic` 的符号和大小 |
| 05 | 120° 导通为什么得到六步换相表 | 每个扇区的正相、负相和悬空相 |

在调节 PI 之前，必须先确认桥、电流、反电动势、转矩和速度之间的因果关系。否则速度偏低时，无法区分是控制器输出不足、换相错位，还是负载已经超过电机可提供的转矩。

速度曲线平滑并不能单独证明 Hall 六步闭环正确。只有 Hall 状态、换相扇区、PWM、测速和速度 PI 在同一模型中闭合，并且启动、扰动、非法 Hall 与过载场景都有可核对的数据和判据，闭环结果才成立。

第一季结束时，读者应能完成一个具体任务：重新运行完整 Hall 六步闭环模型，拿到启动、目标阶跃、负载阶跃、非法 Hall 和过载五组结果，并说明每个 PASS 对应的物理或控制含义。这个能力只覆盖仿真闭环，不等于固件已经能编译或硬件已经能上板。

## 怎样判断一个实验结论可信

| 检查项 | 应看到什么 |
|---|---|
| 模型 | PLECS/Simulink 模型或明确边界的计算脚本 |
| 参数 | 数值、单位、用途和关键限制 |
| 场景 | 至少两个有区分度的命名场景 |
| 数据 | 每个场景的 CSV、trace 或导出表 |
| 图 | 每个重要结论对应真实工具图 |
| 报告 | 指标、PASS/FAIL 或教学观察边界 |
| 复现 | PowerShell 命令、期望输出和失败解释 |
| 结论 | 能从同一份数据独立得到相同判断 |

复现实验时先按这七项逐一核对。缺少模型或源码，就无法确认系统实际执行了什么；缺少数据和图，就无法独立检查结论；缺少场景、判据或复现命令，结果只能视为尚未验证的假设。
